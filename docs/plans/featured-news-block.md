# Featured news block

A hand-curated block of Garland news at the top of the incident browser.
Settled in a `/grill-with-docs` session; vocabulary in [CONTEXT.md](../../CONTEXT.md),
decisions in [ADR 0001](../adr/0001-news-items-are-separate-from-incident-records.md)
and [ADR 0002](../adr/0002-news-items-never-name-anyone.md).

Closes [#27](https://github.com/caleblawrence/garland-tx-police-activity/issues/27).

## What it is

At most five news items above the existing archive browser. Each shows a
rewritten title, a hand-written summary, and a link out. No images. Nobody is
named. Everything gathered but not featured sits in a candidate pool readers
never see.

The archive below is unchanged.

## What it is not

- **Not automatic.** Nothing selects, ranks or promotes an item. Ingest fills a
  pool; a human pins from it.
- **Not linked to records automatically.** The schema supports a link and the UI
  renders one, but only a person creates it.
- **Not a news feed.** It is an index pointing at coverage, five items wide.

## Why not RSS

Checked during the session:

| Source | Result |
|---|---|
| WFAA, FOX 4 RSS | Work. `title`, `link`, `pubDate`, `description` on every item |
| NBCDFW RSS | Returns 200, parses to zero items — feed URL unknown |
| Garland city RSS | Works, 26 items, **zero police stories**. General city newsflash |
| Garland PD press releases | **No feed exists.** Probed every CivicPlus department id |

Two disqualifying facts. The feeds reach back **two days** — WFAA to 29 Aug,
FOX 4 to 1 Sep — so they cannot backfill anything. And the hot-car death of
18 August 2026, which prompted this check, was already outside that window while
still being the most significant Garland story of the month.

Search finds it; feeds never would. Hence Tavily.

The absent press-release feed also removes the only source likely to quote a
case number, which is why record linking is manual (ADR 0001).

## Build order

### 1. Schema

```sql
CREATE TABLE news_items (
    news_item_id   bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    url            text NOT NULL UNIQUE,
    source_title   text NOT NULL,          -- as published, may name people
    source_summary text,                   -- as returned by Tavily
    outlet         text,
    published_on   date NOT NULL,

    featured       boolean NOT NULL DEFAULT false,
    display_title  text,                   -- hand-written, no names
    display_summary text,                  -- hand-written, no names
    featured_at    timestamptz,

    monthly_incident_id bigint REFERENCES monthly_incidents(monthly_incident_id),

    ingested_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX news_items_featured_idx ON news_items (featured, published_on DESC);
```

`url` unique is the cheap dedupe. `source_*` is what arrived; `display_*` is what
publishes. A featured row with no `display_title` is a bug and the export should
refuse it rather than fall back to the source title — that fallback would publish
a name.

Add via `ensure_schema` in `tools.py`, with an explicit `ALTER TABLE … ADD COLUMN
IF NOT EXISTS` for later columns: `CREATE TABLE IF NOT EXISTS` is a no-op against
an existing table, which has already bitten this repo once.

### 2. Ingest — `news_ingest.py`

Follows the shape of `archive_ingest.py`: `--backfill`, `--since`, `--export`,
dry by default.

- Tavily search scoped to Garland policing and public safety.
- **Backfill once** over the last 10 months (Nov 2025 – Sep 2026).
- **Dedupe on ingest.** `url` unique catches exact repeats. Cross-outlet repeats
  need the LLM: the hot-car death returned eight URLs across WFAA, FOX 4, NBCDFW,
  Yahoo, Audacy and Hoodline. Compare each candidate against items already stored
  within a few days of it; store only what is genuinely new.
- Follow-up coverage is **not** a duplicate. An arrest story about an incident
  already reported is a new item.
- `TAVILY_API_KEY` from the environment, `.env`, never committed.

### 3. Pinning

Direct SQL, no tooling:

```sql
UPDATE news_items
   SET featured = true,
       display_title = 'Five-year-old dies in hot car outside Garland home',
       display_summary = 'A child was left in a vehicle during an extreme heat '
                         'warning and died. No charges have been filed.',
       featured_at = now()
 WHERE news_item_id = 42;
```

Writing `display_*` by hand *is* the vague-attribution check. A CLI would only
move it.

To link a record, set `monthly_incident_id` in the same statement.

### 4. Export and page

- `news_ingest.py --export` writes featured items to `work/news_items.json`,
  ordered newest first, capped at five. Refuses to emit a featured row missing
  `display_title` or `display_summary`.
- `archive.js` copies it to `dist/news.json`.
- `archive.html` renders the block above the pills. Each item: title, summary,
  outlet and date, link out. Where `monthly_incident_id` is set, a link down to
  that record in the list below.
- **Empty pool renders nothing.** No block, no placeholder. Consistent with how
  this site already handles absent data.

### 5. Weekly run

Add a step to `scripts/run-weekly.sh` that runs the incremental ingest. It must
run **whether or not the agent stored a week** — a failed parse and stale news are
unrelated failures and should not be coupled.

## Ships dark

Ingest does not publish. The block is empty until someone pins, by design: the
no-names promise can only be made about items a person has read.

## Open, deliberately

- **NBCDFW feed URL** unknown. Irrelevant while Tavily is the source; matters if
  feeds are ever added as a cheap top-up.
- **Automatic record linking.** Deferred, not rejected. Extracting the case
  number the parser currently discards (`2026R038040` in every row) would make it
  exact rather than fuzzy, and is worth doing on its own merits.
- **Tavily query shape and cost.** Unmeasured. Backfill is one bounded run;
  size it before scheduling anything recurring.
